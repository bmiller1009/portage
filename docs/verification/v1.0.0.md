# Portage 1.0.0 verification

Records exactly what was validated for the 1.0.0 GA / public-release-hardening pass — not a marketing summary. Terminology (consistent with the compatibility matrix in the top-level README):

- **SUPPORTED** — the code path exists and is exercised by tests.
- **TESTED** — actually run against real infrastructure at least once.
- **CERTIFIED** — passes the full automated provider-contract suite against real infrastructure.
- **EXPERIMENTAL** — implemented and unit-tested against fakes only; no real infrastructure available to this project to test against.
- **NOT_RUN** — genuinely not exercised this pass; never inferred as passing.

This document is updated as the v1.0.0 milestone's issues close — see the "Last updated" line below for how current it is relative to `HEAD`.

## Known caveats

- VAST NFS-mode and ADLS remain translation-layer-only (EXPERIMENTAL) — no hardware/subscription access. This is the one accepted, documented gap against spec §71's exit criteria.
- `tests/security/` is a placeholder directory; security-relevant tests currently live under `tests/unit/`. Full build-out tracked in #66.
- Chaos-suite Databricks-API-interruption coverage does not exist — there's no way to fault-inject a hosted third-party API the way a self-hosted kind cluster's API server can be killed. Documented as a deliberate limitation, not a gap to silently close.
- `.github/workflows/live-provider.yml` (scheduled live-infrastructure CI) requires repository secrets not yet configured — its first real run is itself part of what verifies it.
