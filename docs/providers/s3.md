# S3 storage provider — Phase 0 live-run results

## Two levels of testing

- `tests/unit/test_s3_provider.py` — `moto`-simulated S3, runs in CI, no network.
- `tests/integration/test_s3_provider_minio.py` — real S3-protocol traffic against a live MinIO deployment (Docker image `minio/minio:latest`, deployed as a Kubernetes `Deployment`/`Service` in namespace `portage-storage` on the Phase 0 remote cluster). Not run in CI (needs the live remote box) — see `.github/workflows/ci.yml`.

Both passed on 2026-08-17.

## MinIO as the S3-compatible backend

VAST wasn't installable in this environment (it's licensed enterprise storage, not open-source software, and is explicitly v0.2 scope per `docs/architecture/spec.md` §65 — Phase 0 only needs S3). MinIO — open source, S3-API-compatible — stands in for "a real S3-protocol endpoint" so the storage provider gets genuinely exercised rather than only mocked. The provider code itself (`providers/storage/s3/provider.py`) has no MinIO-specific logic; it works against MinIO and real AWS S3 identically through the `endpoint_url` config, per spec §49's "S3-compatible implementations through configuration" guidance.

## One nuance worth flagging: network context matters for the endpoint URL

`S3_ENDPOINT_URL` needs a different value depending on **who** is connecting:

- A host-side process (the `plane` CLI, `pytest`, this doc's own verification scripts) reaches MinIO through a `kubectl port-forward` at `http://127.0.0.1:9000`.
- Driver/executor pods running *inside* the cluster (the actual Spark job) must use the in-cluster DNS name, `http://minio.portage-storage.svc.cluster.local:9000` — `127.0.0.1` inside a pod is the pod's own loopback, not the host's.

This isn't a provider bug — the same `S3ConnectionProfile.endpoint_url` field is correct either way — it's an operational detail of *which* endpoint value to hand it, and it's worth documenting because getting it backwards produces a confusing failure (`spark.conf.get()`/S3A calls hang or fail with no obviously-related error, since the app-level code has no visibility into networking).
