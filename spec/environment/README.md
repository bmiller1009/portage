# spec/environment

The `Environment` schema (`docs/architecture/spec.md` §8): a named profile (`onprem-prod`, `azure-prod`) that resolves to a specific execution provider, storage provider, catalog provider, and identity provider. Application developers should normally only ever choose a workload + an environment name — never the underlying infrastructure objects.

`v1alpha1.py` implements a Phase-0-scoped version of this model: just enough (`execution.provider`/`profile`, `data.provider`/`profile`) for `plane run` to pick an execution provider and a storage provider by name — see `examples/environments/k8s-remote.yaml` and `cli/environments.py`. What's deliberately **not** implemented yet, and is v0.1 milestone scope: persisted execution/storage *profiles* (the `execution_profiles`/`storage_profiles` database tables from spec §27), catalog provider resolution, and identity provider resolution. For Phase 0, the connection details behind a named profile (kubeconfig context, S3 endpoint/credentials) are resolved from environment variables in `cli/environments.py`, not a profile registry.
